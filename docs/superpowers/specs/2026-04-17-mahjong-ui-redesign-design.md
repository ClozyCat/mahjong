# 在线麻将前端 UI 重设计方案

**日期**：2026-04-17  
**状态**：已完成设计确认，待用户审阅  
**范围**：前端呈现层全量重设计，不改变现有前后端交互逻辑

## 1. 背景与目标

当前在线麻将前端已具备完整对局能力，但整体视觉语言仍带有较强的旧式系统窗体感，横屏移动端的空间组织也偏向“可用优先”，尚未达到高品质产品界面的沉浸感、统一性与高端感。

本次重设计目标如下：

- 在不改变现有前后端协议、状态流和业务逻辑的前提下，重做大厅、对局桌面、底部操作区、弹窗、结算面板与技能相关面板的视觉与布局。
- 将产品整体风格统一为“新中式雅奢”，呈现典雅、高端、优美、明快的气质。
- 优先兼容移动端强制横屏场景，使用户在手机横持时仍能顺畅完成高频操作。
- 保持操作逻辑符合用户直觉，不增加理解成本，不引入新的流程绕路。

## 2. 设计结论

### 2.1 总体风格

本次 UI 主风格确定为“新中式雅奢”。

风格核心：

- 以玉石青绿作为主视觉主轴。
- 以宣纸米色作为面板与留白底色。
- 以克制暖金作为强调与礼制线条。
- 通过轻书卷感标题、清晰现代正文、柔和层次与克制动效，形成兼顾东方气质和实战效率的产品体验。

### 2.2 重设计范围

本次采用“全量重设计”范围，包含：

- 联机大厅 / 入席页
- 对局主界面
- 手牌与动作操作区
- 玩家信息卡与房间控制
- 技能选择、技能激活、知识说明弹窗
- 结果结算面板
- 其他次级弹窗与悬浮提示

不包含：

- 后端规则逻辑改造
- API / WebSocket 协议修改
- 核心状态结构调整
- 新玩法规则设计

### 2.3 主布局方向

最终布局方向采用“浮岛平衡”方案。

选择原因：

- 相比“中轴礼制”，它更适合移动端横屏的长期实战操作。
- 相比“卷轴分栏”，它更能保留完整牌桌舞台，不会因为侧栏过重而割裂桌面主视觉。
- 它能同时满足“高端观感”和“高频操作可达性”的平衡目标。

## 3. 信息架构与页面骨架

### 3.1 对局主界面骨架

对局主界面采用三段式结构：

1. 顶部轻量悬浮信息条
2. 中央完整牌桌舞台
3. 底部一体化手牌操作 dock

#### 顶部轻量悬浮信息条

顶部信息条用于承载持续关注但不应抢占主视线的信息，包括：

- 牌桌编号
- 当前圈风 / 局数
- 剩余牌数
- 当前主题入口
- 离桌入口
- 其他必要的房间级信息

信息条应做成轻量悬浮、视觉精致、厚度较薄的组件，避免现有厚重标题栏样式。

#### 中央完整牌桌舞台

中央牌桌必须保持绝对视觉中心地位：

- 四家方位完整保留
- 弃牌河完整保留
- 碰杠展示区保留
- 最后一张关键牌、当前行动状态、回合提示围绕桌面展开

桌面视觉从“系统桌面面板感”转向“玉石案台 + 描金边界 + 柔和体积感”的舞台式呈现，但不改变任何逻辑来源。

#### 底部一体化手牌操作 dock

底部区域重构为操作主岛，不再表现为外挂式控制条。

建议布局：

- 左侧：手牌与选中反馈
- 中部：当前提示、倒计时、可执行操作上下文
- 右侧：高优先级动作按钮

目标：

- 在手机横持时贴近双手拇指热区
- 让操作无需跨越大面积屏幕
- 在不压缩牌桌识别度的前提下，优先保证操作效率

### 3.2 大厅页骨架

大厅页改为更具“入席仪式感”的布局，而非系统表单窗口。

建议结构：

- 左侧：品牌题头、当前主题说明、当次配色预览、世界观式引导文案
- 右侧：创建 / 加入牌桌表单
- 模式选择与八番起胡做成更直观的切换卡片

逻辑不变：

- 牌桌编号输入
- 昵称输入
- 模式切换
- 八番起胡切换
- 创建 / 加入按钮行为

### 3.3 信息层级

对局中的信息分为三层：

#### 第一层：绝对关键

- 当前轮到谁
- 当前可执行动作
- 最后一张关键牌
- 倒计时
- 吃 / 碰 / 杠 / 胡 / 技能触发等即时反馈

这一层必须拥有最高视觉优先级，并保证在移动端横屏下依然清晰可读。

#### 第二层：持续关注

- 圈风 / 局数
- 剩余牌数
- 玩家分数
- 房间号
- 座位 ready 状态
- 机器人数量等局内常驻信息

这一层长期可见，但视觉权重低于当前操作提示。

#### 第三层：辅助信息

- 番型参考
- 技能说明
- 房间附加状态
- 装饰性提示

这一层按需展开，不长期抢占屏幕空间。

## 4. 组件级设计原则

### 4.1 玩家信息卡

玩家信息卡采用“玉牌式身份环”设计语言。

每个玩家信息单元整合：

- 昵称
- 风位 / 座位身份
- 分数
- ready 状态
- 是否机器人
- 快捷互动入口

状态表达原则：

- 当前行动玩家：使用柔和金光或玉色脉冲强调
- 非行动玩家：保持低干扰、弱存在感
- 信息必须一眼可扫，但不形成噪音

### 4.2 弹窗体系

技能选择、技能激活、知识面板、番型说明、结算页等统一为“悬浮卷面”体系。

统一特征：

- 外层柔和遮罩
- 中层描金边框或雅致轮廓
- 内层宣纸 / 绢面质感底
- 清晰的信息分区与按钮分级

目的：

- 保证所有弹窗属于同一产品语言
- 避免当前不同 overlay 各自为政的视觉割裂

### 4.3 结算页

结算页应具备较强仪式感，但仍以一眼读懂结果为首要目标。

布局重点：

- 中央明确显示胜负结果
- 番数、番型、输赢变化清晰分栏
- 四家结果按重要性排布
- 下一步操作按钮明确且不冗余

体验目标：

- 赢牌时有明确成就感
- 输牌时也能迅速理解原因和分数变化

### 4.4 操作按钮与操作反馈

按钮分为三类：

- 主操作：最明确、最有层次感
- 次操作：视觉更轻
- 危险 / 取消类操作：语义清晰，但不使用过度刺眼的工业化纯色

反馈原则：

- 操作可执行时应立即显眼
- 不可执行时应安静退场
- 交互反馈强调“礼制引导感”，避免机械感过强的系统按钮体验

## 5. 视觉系统

### 5.1 色彩系统

主色轴采用三元组合：

- 主色：明玉绿 / 青绿色，用于桌面、高亮、当前状态
- 底色：暖宣纸米色，用于大厅、面板、浮条、弹窗
- 强调色：克制暖金，用于描边、焦点、胜利态与高价值按钮

明确要求：

- 不走纯暗黑沉重路线
- 不使用艳俗金色或高饱和霓虹色
- 保持整体明快、透气、温润

### 5.2 材质系统

材质语言分为三类：

- 玉面：用于牌桌核心舞台
- 纸面 / 绢面：用于表单、弹窗、信息面板
- 漆面：用于关键按钮与需要更强确定性的局部组件

它们之间的关系：

- 玉面负责主舞台的温润与沉浸
- 纸面负责信息层的轻盈和可读
- 漆面负责操作层的确定性和反馈感

### 5.3 字体系统

字体采用“标题有书卷感，正文高可读”的双轨策略。

建议：

- 标题 / 技能名 / 结算标题 / 主题标签等高价值位置使用宋 / 楷气质更强的中文衬线风格字体
- 正文、数值、按钮、实时状态信息继续使用现代中文黑体

参考检索结论：

- 可读性优先时，正文保留 `Noto Sans SC`
- 书卷气标题可引入 `Noto Serif TC` 或项目现有可用中文衬线替代方案，仅用于少量标题

原则：

- 不能为了气质牺牲移动端横屏可读性
- 数值信息必须稳定、清晰、不花哨

### 5.4 动效系统

动效目标是帮助理解，而不是炫技。

动效原则：

- 页面与浮层进入：轻微铺展、浮入、柔和过渡
- 出牌 / 胡牌 / 碰杠 / 结算：允许更有力量感的关键动画
- 普通按钮 / 提示：150-300ms 的轻量动效
- 避免持续性装饰动画造成注意力干扰
- 尊重 `prefers-reduced-motion`

### 5.5 牌面与高亮

麻将牌本身以辨识度为第一优先。

允许优化：

- 牌托
- 阴影
- 选中态
- 可操作态
- 最后一张牌高亮
- 焦点牌展示方式

不允许：

- 为了风格化而弱化牌面信息辨识
- 牺牲读牌速度

## 6. 兼容与响应式策略

### 6.1 设备策略

本次设计采用“移动端优先，横屏优先，桌面同源适配”。

具体要求：

- 移动端强制横屏时，页面不能出现横向滚动条
- 手牌、关键提示、动作按钮在小尺寸横屏下仍清晰可用
- 桌面端在同一视觉系统下延展，不分叉为另一套交互逻辑

### 6.2 横屏移动端优先级

小屏横屏场景下优先保证以下内容：

1. 手牌可辨识
2. 按钮可点击
3. 当前提示与倒计时可读
4. 关键牌与关键动作不被遮挡

次级信息应主动收敛：

- 装饰性文字减少
- 辅助标签收窄
- 次级信息采用半透明浮层或更轻量展示

### 6.3 触控规则

交互需满足移动端触控友好原则：

- 操作目标尺寸需适配手指点击
- 常用按钮贴近横屏持机拇指热区
- 不依赖 hover 才能理解状态
- 在需要数字 / 编号输入时使用合适的 `inputmode`

## 7. 工程实现边界

本次改造严格限定在前端呈现层。

允许调整：

- 组件结构的视觉壳层
- DOM 层次与布局组织
- CSS 变量 / 主题 token
- 页面与组件的视觉状态表达
- 动效与过渡效果

不调整：

- API 调用方式
- WebSocket 消息协议
- 业务状态机
- 核心会话与对局逻辑
- 后端规则实现

实现策略建议：

- 保留 `ConnectGate`、`BattleScreen`、`TableStage`、`BottomActionDock` 及各类 overlay 的现有行为接口
- 以“逻辑不动、视觉壳重构”的方式推进
- 在必要时拆分局部视觉子组件，但不引入业务耦合变化

## 8. 验收标准

完成后的前端需要满足以下标准：

- 大厅与对局页视觉统一，不再保留旧系统窗体感
- 新中式雅奢风格稳定落地，典雅、高端、优美、明快
- 移动端横屏下主要操作符合直觉，手位可达
- 牌桌完整、信息层级清晰、关键状态明确
- 技能弹窗、知识面板、结算面板形成统一设计语言
- 不改变既有功能流程和交互逻辑
- 不引入新的学习成本或流程绕路

## 9. 验证策略

实现阶段完成后，至少执行以下验证：

- 前端构建通过
- 现有相关测试通过
- 对大厅页、牌桌页、底部操作 dock、技能弹窗、结算面板进行定向检查
- 在横屏移动端视口与桌面视口下进行实际布局检查

重点验证项：

- 是否出现横向滚动
- 是否存在点击目标过小问题
- 是否有关键信息被遮挡
- 动效是否过长或影响操作节奏
- 视觉对比度是否足够

## 10. 与当前代码结构的关系

结合当前代码结构，主要影响区域预计包括：

- `frontend/src/components/connect-gate/*`
- `frontend/src/components/battle-screen/*`
- `frontend/src/App.tsx`
- `frontend/src/index.css`
- 可能新增少量样式 / 视觉辅助子组件

预计重点工作：

- 重构大厅页视觉与布局
- 重构 `BattleScreen` 总体层级
- 重构 `TableStage` 外围舞台感与信息挂件
- 重构 `BottomActionDock` 为移动端横屏优先的操作主岛
- 统一各类 dialog / overlay 的视觉系统

## 11. 风险与控制

主要风险：

- 桌面重构时影响现有交互可达性
- 横屏移动端布局过度装饰导致信息拥挤
- 视觉风格过重，影响牌面辨识和实战效率

控制原则：

- 一切视觉决策以可读性和可操作性优先
- 牌面辨识优先于装饰
- 关键状态优先于礼仪化装饰
- 保持“高端但不厚重，典雅但不繁复”

## 12. 最终设计结论

本方案采用“新中式雅奢 + 浮岛平衡”的整体方向，以移动端强制横屏为第一适配目标，在不改变现有前后端交互逻辑的前提下，对在线麻将产品进行全量前端视觉重设计。

它不是单纯换皮，而是一次围绕以下三件事展开的系统升级：

- 更高级的视觉语言
- 更合理的横屏操作结构
- 更统一的大厅 / 对局 / 弹窗体验

后续实现阶段应以此文档为设计基线，确保体验提升与工程风险控制同步达成。
